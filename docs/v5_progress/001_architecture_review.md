# KRX v5 — 001. 개발 방식 점검 및 구조 정상화 계획

- 기록일: 2026-11-18 (KST)
- 저장소: cks3210-spec/KRX-Public-Test
- 브랜치: main
- 상위 기준: KRX_V5_MASTER.md (수정하지 않음)

## 1. 기존 개발 방식의 문제점
1. Stage가 계속 추가되어 전체 구조가 복잡해졌다.
2. 동일 기능을 여러 방식으로 개발해 중복 코드와 결과 파일이 증가했다.
3. 오류가 발생할 때마다 별도 프로그램을 만들어 기존 기능과 연결되지 않은 코드가 누적됐다.
4. 완료 기준 없이 다음 단계로 넘어가 실제 완성 여부를 파악하기 어려웠다.
5. 작업 기록을 채팅에 의존해 같은 검증과 작업을 반복했다.
6. 개별 기능 검증에 집중하면서 최종 시스템 통합이 지연됐다.

## 2. 구조 정상화 4단계
1. 전체 프로그램 목록 확보: Python, 워크플로, 데이터, 보고서 파일을 전수 조사한다.
2. 중복 및 연결 관계 분석: 실제 실행 경로, 의존 관계, 중복 및 미사용 가능 파일을 구분한다.
3. 단일 실행 구조 확정: 공식 시장 데이터 수집 → 재무·성장성 분석 → A/B 평가 → 적정 매수가 → 투자 판단 → 5·10·20거래일 성과 검증 → 자동 보고 흐름을 확정한다.
4. 개발 현황 영구 기록: 확정 구조, 검증 상태, 남은 작업, 실행 결과와 커밋을 하위 기록에 누적한다.

## 3. 변경 금지 및 안전 원칙
- KRX_V5_MASTER.md 원본은 수정하지 않는다.
- 기존 완성 목표 7가지는 유지한다.
- 구조 정상화 전에 새로운 Stage나 중복 검증 프로그램을 추가하지 않는다.
- 기존 프로그램은 실행 및 의존 관계 확인 전 삭제하거나 덮어쓰지 않는다.
- 기존 시장 데이터, 재무 캐시, 성과 기록, v4 및 골든크로스는 보존한다.
- 연구용 결과와 검증된 투자 추천을 구분한다.

## 4. 작업 기록 관리
- docs/v5_progress/ 하위에 순차적으로 기록한다.
- 작업 시작 시 마스터 → 하위 작업 기록 → 최근 커밋 → 관련 코드와 실행 결과를 확인한다.
- 작업 완료 시 검증 결과, 미완료 사항, 다음 작업을 기록한다.
- GitHub에 실제 등록되었는지 확인한 후에만 저장 완료로 판단한다.

## 5. 현재 확인된 상태
- KRX_V5_MASTER.md는 main 브랜치에 존재한다.
- Stage25~28 결과 파일이 존재한다.
- Stage25/26은 연구용이며 검증된 투자 추천은 0건이다.
- Stage27 외에도 data/v5_tracking/, data/v5_forward_validation/에 성과 관련 파일이 존재한다.
- 실제 실행 코드의 연결 관계와 중복 여부는 추가 확인이 필요하다.
- 이번 기록 작성으로 기존 프로그램이나 데이터는 변경하지 않았다.
